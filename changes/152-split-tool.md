`scripts/split-tests.ts` splits `test/` into one file per `src/` module, by layer, so parallel branches stop conflicting in the shared import blocks. It places each test by its name prefix from a table and stops on a prefix with no row. A declaration that two or more files use moves to `test/helpers.ts`, so a later edit touches one place; one with module-level state stops the script. `--dry-run` prints the plan and `--out <dir>` writes the tree elsewhere to check it. After the split, `node --test` also lists `test/helpers.ts` as one passing entry with no tests: it loads every `.ts` under `test/`, and this is harmless. The split has run: the tests of `src/<layer>/<module>.ts` are in `test/<layer>/<module>.test.ts`, and `test/architecture.test.ts` checks that each test file is for a `src/` module and that each module has one, but for a short list with no tests yet (#152).
