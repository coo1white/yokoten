Security

The guard now refuses a download that a program would run without a pipe (#830). It reads a pipe across a line break. It reads a download in `$(…)` or a backtick where a command goes. It reads a download handed to a shell, `eval`, an interpreter or `make`. A pipe into an interpreter is refused when the interpreter reads its program from input: `python3 -`, `node`, `perl`, `ruby`, `php`, `lua` or `Rscript -`. A pipe into `make -f -` or `make -f /dev/stdin` is refused. So is a pipe into a small shell a minimal image ships: `ash`, `mksh`, `pdksh`, `yash`, `posh`, `oksh`, `rbash` or `toybox sh`. A download beside a substitution still passes. An interpreter that only prints its version still passes: `perl -v` and `python3 --version`, but not `python3 -v`, which still runs the program. A refusal names the download but never the credentials in its URL, so a token stays private.
