Fixed

The guard reads the publish path the way the tool does. A query string on a `gh api` path no longer hides a release, tag or public-repo call. A variable owner or repo in a `PATCH` does not hide it either. Creating a repo through `gh api user/repos` or `gh api orgs/<org>/repos` is stopped. So is `gh repo create --public=true`. A GraphQL query the shell builds (`query=$(cat …)`, `query=$QUERY`) is refused like a query read from a file. The last GraphQL field wins, as gh reads it. A release tool keeps its name with a version suffix (`npx semantic-release@latest`). `npm publish --dry-run false` is a publish, not a dry run, and the last dry-run flag decides. `git --git-dir` and `GIT_DIR` no longer hide a pushed tag or `push.followTags` (#865). The last `GIT_DIR` is the repo git reads. A `git push` option that takes a value (`-o`, `--repo`) cannot hide a dry run or a tag. The last of `--dry-run` and `--no-dry-run` decides a push, as git reads it. `/graphql` and a full GraphQL URL are read as GraphQL.
