Security

An agent can no longer take gh's token and call GitHub around the guard. For the lead and every worker, the guard now refuses the gh commands that print the token, such as `gh auth token` and `gh auth status --show-token`. It also refuses `gh alias set`, `import` and `delete`, since an alias can run them under another name. The places a login is kept are refused too: `git credential fill`, a credential helper's `get`, `~/.git-credentials`, gh's `hosts.yml` and the system keychain. So is a command that expands `$GH_TOKEN`, `$GITHUB_TOKEN` or the enterprise names, in bash, PowerShell or cmd. Programs that run code, such as `node` and `python`, are refused when the command names one. `GIT_TRACE_REDACT=0` is refused, and the bot's git takes no `-c` or git settings from the environment. The bot no longer passes a pager, editor, browser, ssh program or trace setting on to gh and git. `gh auth status`, `gh pr view` and `curl https://example.com` still pass (#668). `gh workflow disable` is refused for every agent: only the owner turns a workflow off (#668). The privacy check of what gh posts can no longer be skipped by an option value that looks like another option, such as `gh api … -q -XGET -f body=…` (#659).
